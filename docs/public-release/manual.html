1. 사용 전 준비

Windows 10/11 64비트 PC와 인터넷 연결을 준비합니다. Core i5급·메모리 16GB를 기준으로 설계했지만 실제 처리 속도는 CPU 세대, 파일 길이와 다른 작업의 부하에 따라 달라집니다.

  • 일반 사용자는 Python·Node.js·Git을 설치하거나 터미널 명령을 입력하지 않습니다.
  • 국회 제공 자막만 받을 때는 음성 전사 모델이 필요하지 않습니다.
  • 녹음 CPU 기능은 AVX2 지원과 모델·업로드·임시 변환 파일을 보관할 저장공간이 필요합니다.
  • 외부 AI나 릴레이를 사용할 때는 기관에서 허용한 계정과 자료 전송 범위를 먼저 정합니다.
공개판 정보는 릴리스에서 확인하세요.

프로젝트 코드는 MIT 라이선스로 제공합니다. 모델·재사용 코드·실행 도구에는 별도 고지가 적용됩니다. 설치파일 버전, 다운로드 주소, SHA-256과 추가 LLM 연결판의 실제 검증 결과는 공개 릴리스에 확정할 항목입니다. 이 초안은 과거 시험판 파일이나 운영 사이트로 연결하지 않습니다.

2. 설치와 첫 실행

  1. 공식 설치파일 확인공개 릴리스의 Windows x64 설치파일과 검증 정보를 확인합니다. 기관 PC에서 설치가 제한되면 담당 관리자에게 확인합니다.
  2. 개인 계정용 설치설치 마법사를 따라 설치합니다. 설치가 끝나면 바탕화면이나 시작 메뉴에서 앱을 엽니다.
  3. 기관명 저장시작 화면의 기관 설정에 기관명을 입력합니다. 이 이름은 우리 기관 언급과 관련 기록을 찾는 데 사용합니다.
  4. 기록 화면 열기AI를 바로 쓰려면 계정 또는 API 연결을 진행합니다. 우선 기록부터 하려면 AI 연결 없이 기록 열기를 선택합니다.
앱 시작, 기록 화면 열기, 회의 수집 시작은 서로 다른 단계입니다. 실제 수집은 회의를 만들고 시작을 눌렀을 때 시작됩니다.

설치파일을 바꿔도 기존 사용자 기록을 새 설치파일에 넣어 옮기는 방식은 사용하지 않습니다. 새 설치와 기존 기록 보존은 별도로 확인합니다.

3. ChatGPT 계정과 Ollama·API 연결

시작 화면의 AI 연결에서 사용할 방식을 정합니다. ChatGPT 로그인이 필수인 것은 아닙니다. Ollama·API 연결 설정을 누르면 기록 설정의 AI 연결 화면으로 이동할 수 있습니다.

연결 방식사용자가 할 일구분할 점
ChatGPT 계정ChatGPT 로그인에서 공식 브라우저 로그인과 권한 확인을 마친 뒤 앱으로 돌아옵니다.API 키를 로그인 칸에 입력하지 않습니다. 로그인 완료와 실제 요청 성공은 별개입니다.
Ollama이 PC에 준비된 Ollama 서버와 모델을 확인하고 프리셋을 고른 뒤 모델 이름을 입력합니다.이 앱이 Ollama 서버나 모델을 자동 설치하지 않습니다. 무인증 로컬 서버는 키를 비울 수 있습니다.
LM Studio준비된 로컬 서버를 켜고 해당 프리셋과 모델을 선택합니다.서버를 설치한 것과 실제 모델 요청을 받을 준비가 된 것은 다릅니다.
OpenAI API제공자 프리셋·모델·별도 API 키를 설정합니다.ChatGPT 계정 로그인과 API 키 인증은 별개입니다. 계정의 구독 상태로 API 사용 권한을 대신하지 않습니다.
사용자 지정 호환 서버기관 관리자가 안내한 서버 주소·모델·인증 조건을 설정합니다.주소와 자료 전송 대상을 확인합니다. 사내 서버와 외부 서버를 구분합니다.
AI 없이 기록AI 연결 없이 기록 열기로 회의를 수집·열람합니다.AI 초안은 대기·실패하거나 규칙으로 정리될 수 있습니다. 결과의 생성 출처를 확인합니다.

연결 시험은 실제 요청입니다

서버·모델·키를 저장하고 연결 시험 또는 연결 테스트를 누릅니다. 짧은 텍스트 요청을 보내는 기능입니다. 오류가 나면 버튼을 연속해서 누르기보다 로그인·서버·모델·사용 가능 상태를 살펴보세요.

선택한 LLM은 종료 질의의 본문·역할 보완과 요약에 사용합니다. 서비스에 따라 자료 전송·과금·사용량·모델 실행 조건이 다릅니다. 무료·무제한·완전 오프라인을 모든 방식에 공통으로 약속하지 않습니다.

AI 연결이 실패해도 자막 수집·원문 저장을 AI 완료에 묶지 않습니다. 수집 중 다시 로그인할 수 있는 안내와 AI 처리 상태를 각각 확인합니다.

추가 연결판의 제공자별 실제 자막·녹음 검증은 공개 전 확정할 항목입니다. 메뉴 연결·로그인·한 번의 요청 성공이 긴 회의의 품질과 처리 완료를 보장하지 않습니다.

4. 국회 자막으로 회의를 기록하기

  1. 새 수집 세션기록 화면에서 새 세션을 만들고 국회 AI자막 수신을 고릅니다.
  2. 회의 선택오늘 국회 중계 목록에서 필요한 회의를 고릅니다. 자동으로 채워진 제목·위원회·피감기관·명단을 확인합니다.
  3. 시작세션을 만든 뒤 시작을 누르고 수집 상태와 최근 수신 시각을 확인합니다.
  4. 실황과 종료 질의 구분진행 중에는 수신 기록을 보고, 질의가 끝나면 보정 대기·진행·완료 상태와 요약을 확인합니다.
  5. 마칠 때 종료회의가 끝나면 수집을 종료하고 저장된 기록을 검토합니다. 자동 종료 기능이 있더라도 종료 상태를 직접 확인합니다.

회의 목록에 항목이 있다는 사실만으로 모두 생중계 중인 것은 아닙니다. 회의 정보와 실제 중계 상태를 확인하세요. 국회 제공 자막의 수신 오류·누락·부분 자막도 기록 품질에 영향을 줍니다.

국회 원수신 자막 보존→실황 역할·질의 추정→종료 질의 보정·요약→담당자 검토

5. 녹음·녹화 파일을 정리하기

회의 음성을 나중에 정리할 때 사용합니다. 자막 수신과 별도의 입력 방식입니다.

  1. CPU 전사 준비 확인설정의 음성인식에서 Nemotron 3.5 ASR · Windows CPU를 고르고 필요한 전사·화자 분리 파일의 준비 상태를 확인합니다.
  2. 녹음 파일 선택새 수집 세션에서 녹음 파일을 선택합니다. 화면에서 허용하는 WAV·MP3·M4A·MP4·WebM·OGG·AAC·FLAC 파일을 올립니다.
  3. 시작 시각 확인녹음 0초의 실제 시각을 알면 입력합니다. 비우면 업로드 시각 기준으로 표시될 수 있습니다.
  4. 처리 시작과 진행 확인화자 분리·전사 상태를 확인하며 기다립니다. 파일 전체를 먼저 분석하므로 바로 발언이 나타나지 않을 수 있습니다.
  5. 전사 후 보정 확인전사된 본문과 질의 묶음을 확인한 뒤 종료 질의의 AI 보정과 요약 상태를 확인합니다.
음성 길이보다 처리가 오래 걸릴 수 있습니다.

CPU만 사용하는 기능입니다. 긴 녹음, 여러 화자, 겹친 말, 낮은 음질과 다른 PC 작업에 따라 지연이 커집니다. 특정 PC의 짧은 시험 시간을 모든 PC의 실시간 성능으로 보장하지 않습니다.

MP3·영상 등은 음성 변환 도구가 필요할 수 있습니다. 변환 도구를 찾지 못했다는 안내가 나오면 릴리스의 지원 방법을 확인하거나 기관 관리자에게 문의하세요.

음성 파일을 전사해 글로 만든 뒤 외부 LLM을 선택하면, 보정에 필요한 전사 글과 문맥이 해당 서비스로 전송될 수 있습니다. CPU 음성인식이 로컬이라는 이유로 전체 AI 과정도 모두 로컬이라고 보지 않습니다.

6. 모델을 준비하고 CPU 사용량 정하기

구성하는 일준비와 한계
Nemotron 3.5 ASR음성 → 글선택한 전사 모델을 준비합니다. 숫자·부정·고유명사가 틀릴 수 있습니다.
Nemotron 3 Diarization목소리별 시간 구간·겹침 후보동봉 상태와 준비 안내를 확인합니다. 최대 8개 목소리 후보를 다루며 실명 판별은 아닙니다.
Julia-1 · 선택글의 질의·답변·진행·기타 역할 후보공식 파일 약 0.6GB를선택 후 준비합니다. 요약기·음성인식기·실명 확인기가 아닙니다.
Jev · 선택외부 역할 판정 후보별도 키와 기관의 외부 전송 승인이 필요합니다. 기본 사용의 필수 항목은 아닙니다.

준비 순서

  1. 설정에서 원하는 기능을 선택합니다. 선택만으로 파일 준비가 끝난 것은 아닙니다.
  2. 표시된 용량과 각 모델의 라이선스·고지를 확인합니다.
  3. CPU 전사·화자 분리 모델 준비 또는 Julia-1 모델 준비를 누릅니다.
  4. 완료·실패·취소 상태를 확인합니다. 중간 파일이 있다는 이유로 준비 완료로 판단하지 않습니다.

음성 모델은 약 1.1GB 이상의 준비 공간 외에도 녹음과 임시 변환 파일을 위한 여유 공간이 필요합니다. 모델 파일 용량은 실행 중 메모리 사용량과 다릅니다.

음성 CPU 사용량의 자동은 PC에서 사용할 수 있는 논리 CPU를 활용하는 방식입니다. 수동 상한을 정할 수도 있습니다. 다른 앱이 느려지면 수동 상한을 검토하세요. Julia와 함께 처리될 때의 우선순위 조정은 처리 속도를 보장하는 기능이 아닙니다.

중계·브라우저 음성은 약 30초 분량을 모아 빠른 CPU 설정으로 화자를 나눌 수 있어 발언 표시가 늦게 나타납니다. 지연이 커지면 화자 표시를 보류하고 전사를 계속할 수 있습니다.

7. 본문과 화자를 검토하는 법

앱은 수집 원문과 실황 추정, 종료 질의 보정본을 구분해 보관합니다. 기본 화면은 사용 가능한 최신 저장 표시본을 보여줍니다. 자동 보정이 원문이나 사람의 수정·검수를 지워야 한다는 뜻은 아닙니다.

가상 예시 · 실제 회의 자료가 아닙니다

목소리 1질의 후보역할 확인 필요위원 가: “자료를 다음 회의 전까지 제출하시겠습니까?”

목소리 2답변 후보답변자 나: “확인한 뒤 제출 가능 여부를 말씀드리겠습니다.”

이 답변을 “제출을 약속함”으로 확정하면 안 됩니다. 목소리 번호와 역할 후보만으로 실명도 확정할 수 없습니다.

꼭 확인할 다섯 가지

  1. 부정: “하지 않는다”가 “한다”로 바뀌지 않았는지 확인합니다.
  2. 숫자·시점: 금액, 날짜, 횟수, 기한과 인지 시점을 원문과 대조합니다.
  3. 이름·기관: 발언자 후보와 직접 호명·명단 근거가 맞는지 확인합니다.
  4. 질문과 답변: 짧은 재질문, 끼어들기, 진행 발언이 한 사람의 말로 묶이지 않았는지 봅니다.
  5. 불확실 표지: 본문 확인 필요·역할 확인 필요·성명 확인 필요가 남아 있는지 확인합니다.

완료와 정확함은 다릅니다

일부 보정이나 부분 결과는 일부 구간을 보정하지 못했거나 요약 일부를 보류했다는 뜻일 수 있습니다. 원문을 유지한 문장도 남을 수 있습니다. 완료 표시·문장 개수·모델 점수만으로 내용이나 화자의 정확도를 판단하지 않습니다.

근거를 확인한 뒤 필요한 본문·화자·요약을 직접 수정하거나 검수합니다. 사람이 수정한 본문, 수동 화자, 검수한 블록과 사람이 수정한 요약은 자동 처리로 덮어쓰지 않는 대상입니다.

8. 요약·요구자료·약속 확인

위원별 질의와 회의 요약을 보고 우리 기관 언급, 요구자료, 약속·검토사항, 지적사항을 확인합니다. 요약의 생성 출처와 입력 범위도 함께 봅니다.

  • 규칙 초안: AI 요청 없이 문장에서 뽑아 정리했을 수 있습니다.
  • AI 요약 초안: 연결한 서비스가 생성했더라도 사실 확인을 대신하지 않습니다.
  • 보정 문서 참조 요약: 해당 보정 문서와 같은 판본의 요약인지 확인합니다.
  • 사람 수정 요약:담당자가 수정한 내용과 자동 결과를 구분합니다.

전사에 중요한 내용이 있어도 요약에서 빠질 수 있습니다. 질문 주제뿐 아니라 답변의 부인·조건·인지 범위·미확정 사항·자료 요청과 약속도 본문에서 대조하세요.

질의가 잘 묶이지 않은 회의의 전체 요약은 저장된 확정 발언을 입력으로 삼을 수 있습니다. 표시된 시간 범위와 입력 건수, 일부 발언만 반영됐는지 확인합니다. 전체 저장 발언을 입력했다는 사실이 실제 회의 전체를 빠짐없이 수집했다는 뜻은 아닙니다.

9. 단독 HTML로 보관하기

  1. 마지막 저장 상태 확인보정이 진행 중인지, 확인 필요 표시와 요약 누락이 남았는지 살펴봅니다.
  2. 내보내기 선택회의 화면의 내보내기 → 단독 HTML을 선택하고 파일을 저장합니다.
  3. 파일을 다시 열어 확인저장한 HTML을 브라우저에서 열어 제목·회의 범위·본문·요약·원문 연결과 미보정 구간이 있는지 확인합니다.
  4. 전달 범위 결정기관의 보관·공유 기준에 맞는 위치에 저장하거나 필요한 담당자에게만 전달합니다.

단독 HTML은 서버 없이 읽을 수 있는 기록 보존본입니다. 앱 DB 전체, 계정, 원음 파일, 모든 과거 보정 후보·작업 이력을 함께 백업하는 기능은 아닙니다. 필요한 원음·업로드 자료의 보관은 별도 절차로 확인합니다.

HTML에도 회의 본문과 인물·기관 정보가 포함될 수 있습니다. 인터넷 없이 열리는 파일이라고 공개 자료가 되는 것은 아닙니다. 공개 샘플·문제 신고·저장소에는 실제 기록 대신 가상 예시를 사용하세요.

10. 동료 열람 사이트는 선택 기능입니다

로컬 기록부터 사용할 수 있습니다. 동료 열람이 필요하면 시작 화면의 릴레이 열람 준비에서 기관이 허용한 외부 서비스 계정·작업 공간·저장공간·요금 조건을 확인합니다.

  1. 공식 로그인과 기관의 계정 권한을 확인합니다.
  2. 앱 안내에서 팀·저장공간·요금제를 직접 확인하고 선택합니다.
  3. 사이트 주소 생성과 사이트 로그인, 현재 PC의 원본 연결 검증 완료를 각각 확인합니다.
  4. 다른 기기에서 실제 기록이 보이는지도 확인한 뒤 주소와 열람 방법을 필요한 동료에게 전달합니다.

PC가 꺼지거나 절전·인터넷 단절이 생기면 원본 연결이 끊길 수 있습니다. 외부 서비스의 로그인·요청·응답 캐시 등도 별도로 사용합니다. 모든 자료가 PC에만 남는다고 가정하지 않습니다.

앱 업데이트와 이미 배포된 사이트의 화면 업데이트는 별개입니다. 기존 사이트 업데이트가 필요한지 확인하고, 결과가 불명확하면 연속 재배포하기 전에 기존 결과를 확인합니다. 일반 사용자가 공유기 포트를 열 필요는 없습니다.

11. 기록 보존·백업·업데이트

행동의미
기록 엔진 종료·앱 종료실행 중인 앱 작업을 마칩니다. 저장 기록 삭제와 다릅니다.
앱 업데이트·제거설치파일 교체나 제거가 사용자 기록 삭제를 뜻하지 않습니다. 중요한 자료는 미리 백업하고 업데이트 후 기존 기록을 확인합니다.
회의 삭제해당 회의의 발언·요약·후속조치·원음·업로드 파일이 함께 삭제될 수 있습니다.
보존 기간 설정설정한 기간이 지난 원음·자막 원본·종료 기록은 자동 정리 대상이 됩니다.

설정의 보존 기간에서 원음·국회 자막 원본·종료 기록을 각각 확인합니다. 기록 보존 일수의 0은 기한 없이 보관한다는 뜻입니다. 원음의 0은 새 원음 저장을 사용하지 않는 뜻이므로 같은 숫자를 모든 항목에서 같은 의미로 해석하지 않습니다.

기관 백업이 필요하면 수집·처리를 마치고 앱을 정상 종료한 뒤 담당자가 승인한 백업 절차를 사용합니다. 기록 전체와 계정 파일을 한 번에 공개 저장소로 올리는 방식은 사용하지 않습니다. HTML 보관은 전체 앱 데이터 복원용 백업과 다릅니다.

12. 자료가 이동하는 곳

동작자료 흐름
국회 자막·중계 조회국회 제공 서비스에서 회의 목록·자막·중계 음성을 받습니다.
로컬 CPU 모델이 PC에서 음성을 전사하거나 역할 후보를 만듭니다. 최초 파일 준비는 공식 배포처를 사용합니다.
외부 LLM·Jev 선택선택한 서비스에 보정·요약·판정에 필요한 글과 문맥을 보낼 수 있습니다.
릴레이 연결별도 외부 사이트·저장공간과 연결해 동료 열람에 필요한 요청·응답 등을 처리합니다.
단독 HTML 전달저장한 본문·요약 등 기록 내용이 파일에 들어가 전달받은 사람이 열람할 수 있습니다.

계정과 키는 앱의 안내된 연결 화면에서만 관리합니다. 문제 신고에 키·로그인 화면의 개인 정보·원음·실제 회의 본문을 그대로 첨부하지 않습니다. 진단용 화면과 발생 시각, 비밀값을 제거한 오류 안내부터 전달하세요.

13. 문제가 생겼을 때

회의 목록을 불러오지 못합니다

인터넷과 국회 중계 상태를 확인하고, 화면의 오류 안내를 기록합니다. 회의 목록 조회 실패와 이미 수신 중인 회의의 상태를 구분하세요. 반복 클릭으로 수집을 새로 시작하지 않습니다.

로그인은 됐지만 AI 요청이 실패합니다

연결 시험 결과, 계정의 사용 가능 상태, 선택한 모델을 확인합니다. API를 선택했다면 해당 제공자·서버·키의 연결을 별도로 확인합니다. 원문 수집 상태와 AI 실패는 각각 확인하세요.

Ollama·LM Studio 연결이 안 됩니다

선택한 서버가 켜져 있고 요청할 모델이 준비됐는지 확인합니다. 프리셋·서버 주소·모델 이름이 실제 준비한 값과 맞는지 봅니다. ChatGPT에 로그인해야 해결되는 문제와 구분합니다.

녹음 처리 중 발언이 아직 없습니다

화자 분리·전사 단계가 진행 중인지 확인합니다. 파일 전체 분석과 CPU 처리에는 시간이 걸립니다. 같은 파일을 여러 번 시작하기보다 처리 상태·오류·디스크 여유를 확인하세요.

본문이나 이름이 틀렸습니다

원문과 필요한 경우 원음·공식 회의록을 대조합니다. 확인 필요 표지를 살피고 본문·화자를 직접 검수합니다. 익명 목소리 번호나 모델 점수로 실명을 확정하지 않습니다.

요약이 일부 없거나 부분 결과입니다

본문에 실제 내용이 있는지, 요약의 입력 범위·보류·출처를 확인합니다. 빠진 쟁점은 본문에서 직접 확인하고 필요한 경우 담당자가 수정합니다.

다른 앱 또는 포트가 사용 중이라고 나옵니다

같은 앱이 중복 실행됐는지 확인합니다. 앱은 다른 프로그램을 자동 종료하지 않습니다. 어떤 앱인지 모르면 기관 관리자에게 오류 안내를 전달하세요.

내보낸 HTML에 최신 결과가 없습니다

앱의 보정 작업과 저장 상태가 끝났는지 확인하고 내보낸 시각·회의 범위를 확인합니다. 화면에 보이던 중간 상태와 마지막 저장 상태를 구분합니다.

14. 업무를 마칠 때 확인

  • 해당 회의의 수집이 종료됐습니다.
  • 보정·요약의 완료·부분·실패 상태와 확인 필요 구간을 확인했습니다.
  • 핵심 질문과 답변, 부정·숫자·이름, 요구자료·약속의 귀속을 대조했습니다.
  • 우리 기관 관련 후속조치와 누락된 요약 쟁점을 확인했습니다.
  • 단독 HTML을 저장하고 직접 다시 열어 봤습니다.
  • 원음과 기록의 보존 기간·기관 백업 위치·공유 범위를 확인했습니다.
  • 기록 엔진과 앱을 정상 종료했습니다.
