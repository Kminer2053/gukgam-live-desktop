# 공개 소스 범위와 배포 확인

공개 저장소는 [Kminer2053/gukgam-live-desktop](https://github.com/Kminer2053/gukgam-live-desktop)입니다. Windows **0.1.0-preview.24** 설치파일은 게시 준비 중이며 아직 제공되지 않습니다. 설치파일·해시·릴리스 노트는 [GitHub Releases](https://github.com/Kminer2053/gukgam-live-desktop/releases)에서 안내합니다. GitLab 미러는 주소가 확정되면 추가합니다.

## 공개 경계

공개 소스는 선별한 파일의 새 스냅샷입니다. 비공개 개발 이력, 실제 회의 본문·원음, 운영 진단·계정·토큰·개인 설정은 포함하지 않습니다. 공개 예시와 시연에는 가상 기관·가상 발언을 사용합니다. 파일 목록과 검사는 공개 산출물 자체를 기준으로 확인합니다.

## 파일 분류

| 분류 | 후보 경로 | 처리 |
|---|---|---|
| 제품 소스 | `gukgam/`, `desktop/src/`, `cloud/`의 코드·화면·정적 자산 | 개인 경로·운영 주소·실제 발언·내장 비밀값을 검토한 뒤 포함 |
| 빌드 입력 | 엔진 spec, 의존성 목록·lockfile, 필요한 빌드 스크립트·스키마 | 새 공개 스냅샷에서도 필요한 파일이 모두 있는지 확인 |
| 공개 문서 | 새 README, `docs/public-release/` | 가상 예시와 확정한 릴리스 정보만 사용 |
| 개별 라이선스 | `desktop/LICENSES/`, 자산 고지·vendor 헤더 | 내용·저작권 고지를 보존하고 설치물 포함 여부 대조 |
| 내부 인계·진단 | `AGENTS.md`, `HANDOFF.md`, 일반 개발 문서·`docs/legacy/`, `docs/evidence/` | 기본 제외. 필요한 기술 설명은 민감 자료 없이 새로 작성 |
| 실제 시험 fixture | `tests/fixtures/`의 회의 원문·원수신·음성·실명 라벨 | 공개 제외. 시험용으로 수집했거나 인터넷 자료라는 이유로 공개 샘플로 전환하지 않음 |
| 일반 테스트 | `tests/`, `desktop/tests/` | 코드 안의 실제 발언·이름·외부 주소·fixture 의존을 점검한 합성 테스트만 별도 선별 |
| 실행 산출물 | `outputs/`, `data/`, `records/`, 로그·캡처·업로드·DB·모델·빌드 폴더 | 소스 스냅샷에서 제외. 설치파일은 별도 검증한 릴리스 자산으로만 취급 |
| 계정·환경·원격 설정 | 환경 파일, vault·암호화 파일, 토큰, 인증 자료, 배포 연결 설정, `.git` | 열어 값을 확인하거나 가져오지 않고 경로 단계에서 제외 |

`desktop/src/storage/vault.ts`와 보안 파일 기능의 소스는 실제 vault 파일과 다릅니다. 이름에 `vault`가 있다는 이유로 제품 보안 소스를 삭제하거나, 반대로 실제 저장 자료를 소스라고 포함하지 않습니다.

## 고지와 링크 정리

공개 고지는 [제삼자 고지](THIRD_PARTY_NOTICES.md)를 기준으로 정리하며, `desktop/LICENSES/`의 개별 원문을 보존합니다. 고지의 상대 링크는 최종 공개 파일 트리에서 검사합니다.

프로젝트 소스코드에는 [MIT 라이선스](../../LICENSE)가 적용됩니다. 루트 라이선스와 프로젝트 package 메타데이터를 함께 제공하며, 모델·제삼자 자산은 각 라이선스를 따릅니다. 패키지의 `private` 설정은 npm 게시 방지 용도입니다. 설치 패키지는 루트 라이선스를 `resources/LICENSE.txt`로 동봉하도록 구성하며, 최종 설치 산출물에서도 포함 여부를 확인합니다.

## 동작하는 소스와 공개 시험 묶음은 따로 확인

실회의 fixture를 제외한 뒤 기존 전체 pytest·CI가 그대로 재현된다고 쓰지 않습니다. 제품 코드·화면·스키마·빌드 입력을 빠짐없이 공개하는 검토와, 실제 기록 없이 재현할 수 있는 합성 테스트 묶음의 검토는 구분합니다. 예전 시연 입력의 실제 회의 경로를 공개 샘플로 남기지 않습니다.

선별한 합성 테스트만 사용해 새 스냅샷에서 실행하고, 포함한 시험 범위와 제외한 실제 자료 의존을 명시합니다. 기존 비공개 저장소의 시험 성공 숫자를 공개 스냅샷의 시험 숫자로 복사하지 않습니다.

## 검사 순서

1. 자막·녹음 실제 실행 검토 결과와 알려진 한계를 릴리스 기준으로 기록합니다. 실제 본문·원음은 공개 증거로 포함하지 않습니다.
2. 공개 저장소·MIT 라이선스·릴리스 버전이 배포 정보와 일치하는지 확인합니다.
3. 추적 파일의 경로를 분류하고, 제외 경로는 파일 본문을 읽거나 복사하기 전에 차단합니다.
4. 허용 후보 코드·공개 문서에서 비밀값 패턴·개인 절대경로·운영 주소·실제 기록 식별자를 검사합니다. 발견 내용은 값 대신 파일·줄·종류만 보고합니다.
5. 실제 발언·이름·화면 이미지와 라이선스는 별도로 검토합니다. 자동 패턴 검사는 내용·권리 검토를 대신하지 않습니다.
6. 새 소스 묶음에서 빌드 입력·정적 자산·스키마·라이선스·매뉴얼 링크를 확인합니다.
7. 별도 합성 시험과 최종 Windows 설치파일을 검증하고 해시·파일 목록을 고정합니다.
8. 가상 예시만 든 아이콘·HTML 매뉴얼·시연 영상을 확인한 뒤 새 공개 저장소와 지정 배포처에 게시합니다.

## 검사 도구

`scripts/audit_public_snapshot.py`는 **검사만** 수행합니다. Git 추적 파일 경로와 명시한 신규 공개 문서·검사 소스만 대상으로 삼고, 제외 경로의 본문은 읽지 않습니다. 네트워크·모델·DB·계정 접근과 복사·압축·push는 하지 않습니다. 보고서는 내부 검토용이며 그대로 공개 샘플로 올리지 않습니다.

이 도구의 후보 목록과 최종 공개 파일 목록은 구분합니다. [배포 확인 메타데이터](RELEASE_MANIFEST.json)는 설치파일·패키지 고지·매뉴얼 등 각 항목의 실제 확인 근거에 따라 갱신합니다. 문서가 있다는 이유만으로 미확인 항목을 완료 처리하지 않습니다.
