# 추출 항목의 중복 판정 키 이전

중복 판정 키는 서명이나 로그인에 쓰지 않는다. 같은 발언에서 같은 자료 요구·후속조치가 다시 생성되는 것을 막는 내부 식별 값이다. 새 소스는 SHA-256 전체 값과 정규화한 생성 입력을 함께 저장한다. 공백 차이는 무시하되 입력 사이의 구분 문자가 본문과 섞여 같은 키가 되는 문제도 방지한다.

## 기존 기록 보존

DB 스키마 6으로 처음 열 때 기존 항목의 키와 새 식별 메타데이터를 이전한다. 원발언, 요지, 인용, 항목 ID, 담당 부서, 기한, 메모, 처리 상태와 사람의 검토 표시는 바꾸지 않는다. 다른 표시용 테이블의 지문도 이 이전 대상이 아니다.

- 자동으로 생성한 기존 항목은 저장된 발언 ID·종류·인용 또는 요지로 새 키를 계산한다. 같은 내용을 재추출해도 기존 ID를 유지한다.
- 사람이 이미 수정한 기존 항목은 생성 당시 요지나 인용을 확실히 복원할 수 없다. 같은 발언과 종류, 또는 발언이 없는 경우 같은 질의 블록의 항목을 자동 재생성으로 우회하지 않도록 보존한다. 연결 근거 자체가 없는 경우에는 임의로 합치지 않는다.
- 같은 키로 수렴하는 기존 행은 삭제하거나 덮어쓰지 않는다. 구별 가능한 키를 부여하고 자동 대체를 보류한다. 새 항목의 중복 판정도 해시만 비교하지 않고 생성 입력을 함께 비교한다.
- 중복 판정을 사용하지 않았거나 이미 대체 처리되어 키가 비어 있는 항목은 빈 키를 유지한다.

키 교체와 스키마 판본 기록은 한 데이터 트랜잭션에서 처리한다. 도중에 실패하면 키 교체가 롤백되며 다시 시도할 수 있다. 새 열의 추가와 테이블 생성은 별도 준비 단계다. 이전을 마친 DB를 다시 열거나 같은 이전 함수를 다시 호출해도 사람의 수정 내용을 기준으로 키를 재계산하지 않는다.

새로 만드는 항목에는 생성 입력을 처음부터 보관한다. 이후 사람이 요지나 인용을 바꾸어도 그 생성 입력은 자동으로 덮어쓰지 않는다. 이 정보는 기존 항목을 재처리할 때 ID와 수동 수정을 함께 보존하는 데 사용한다.

## 확인 범위

공개 합성 시험은 이전 형식 DB, rule 재추출, LLM 결과 재동기화, 수동 요지·인용 변경, 충돌, 빈 키, 재시작과 중간 실패를 다룬다. 실제 회의 자료·계정·모델 호출을 시험 입력으로 사용하지 않는다.

기존 정식 0.1.1 설치파일과 태그는 이 소스 수정으로 교체하지 않는다. 의존성과 데이터 이전을 담는 다음 설치판은 새 버전으로 별도 빌드·설치 검증해야 한다. 이 문서의 존재는 현재 PC의 운영 DB가 이미 이전됐다는 뜻이 아니다.
